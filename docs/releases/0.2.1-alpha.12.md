# js-ffi 0.2.1-alpha.12

本预发布版本对齐实际已发布的 Calcit CLI / npm `@calcit/procs` **0.29.0-alpha.1**，与模块自身版本 `0.2.1-alpha.12` 区分。本模块仍通过 Git tag 分发，不发布 npm 包；npm 中的 `@calcit/procs` 是 Calcit runtime，不是这个模块。

## 变化与边界

- `KeyboardEventHost` 与 `MouseEventHost` 现在用 `('requires EventHost)` 声明继承：键盘和鼠标事件可以直接传给要求 `EventHost` 的位置（例如 `event-stop-propagation!`），并能读取 `:event-type`、调用 `.prevent-default!` 等共享成员，它们不再各自重复声明 `.prevent-default!`。反方向（`EventHost` 到 `KeyboardEventHost`）仍然需要适配器里的宿主种类检查，`PointerEventHost` 与 DOM 元素 trait 保持独立。
- `js-ffi.shared/normalize-error` 对 `name` 与 `message` 增加已有的 `expect-string` 校验，使 `JsError` 字段在 Calcit 0.29.0-alpha.1 的 lowering 后仍被证明为 String；两条分支原本就返回字符串，运行时行为不变。
- `promise-create` 的 executor 使用 `Fn(Fn(T)->Unit, Fn(E)->Unit)->Unit`：resolve/reject 可有不同的精确类型，但未使用的 reject 也需要完整 Fn，开放宿主错误可用 `Fn(JsNullish<JsObject>)->Unit`，不再用 DynFn。非泛型 `PromiseHost` 的 `.then!` / `.catch!` 及 `promise-observe!` 的 callback 参数为 `JsNullish<JsObject>`；通过既有 `expect-string` / `normalize-error` 后再进入具体 payload 类型，不能把 Promise 宿主句柄当作 payload。两个普通 Calcit recipes 见 `docs/recipes.md`。这是有意收紧的静态合同；Promise normalization、thenable assimilation、微任务顺序及 ready 抛错后进入 failed 的运行时行为保持不变。
- `deps.cirru`、npm runtime、lockfile 与 Yarn quarantine 例外使用相同的精确版本 `0.29.0-alpha.1`。本版本还包含 23 个增量宿主 API（见 `docs/standard-host-adapters.md`）；已审阅的宿主断言 baseline 不增加。
- 新增 type-contract 测试：键盘/鼠标事件传入 `EventHost` 参数通过检查，`EventHost` 传入键盘事件参数被拒绝，且不含继承声明的源码上前一个用例会失败。
- `search-params-create` 使用既有 `UrlSearchParamsHost` 的受检 `js-cast`，替换模块内的 unsafe 断言；保留原宿主对象身份与方法的 `this`，构造只执行一次，检查不触发 `size` getter。错误方法形状在边界拒绝。
- 模块文档的分类修正为 Calcit 支持的 `tools`、`features` 和 `reference`。安装模块后可通过既有 `docs list/search/read --module js-ffi` 发现 API 查询工具、宿主边界和受检异步适配器说明。

## 升级顺序

[0.2.1-alpha.12](https://github.com/calcit-lang/js-ffi/releases/tag/0.2.1-alpha.12) 已作为 Git tag 和 GitHub prerelease 发布。安装时固定该 tag，而不是 main。

1. 安装 Calcit CLI `0.29.0-alpha.1`，核对 `calcit -v`。
2. 将应用 `deps.cirru` 的 Calcit 版本与 npm `@calcit/procs` 精确版本同时调整为 `0.29.0-alpha.1`，再更新 js-ffi 模块版本为 `0.2.1-alpha.12`。
3. 执行模块安装与 npm 安装，确保所有依赖使用同一个 runtime 实例。
4. 检查应用中的 `promise-create` executor 与 Promise callbacks：补齐 reject 的 Fn 签名，用 decoder 处理观察值，再运行 `caps verify --toolchain`、应用严格检查、实际 Node/browser 构建和项目测试。

在已安装模块的应用目录查询文档：

```sh
calcit docs list --module js-ffi
calcit docs search query --module js-ffi
calcit docs read typed-host-boundary.md --module js-ffi
```

Calcit `0.29.0-alpha.1` 仍是预发布版本，不代表 Calcit 0.29.0 milestone 全部完成。
