# js-ffi 0.2.1-alpha.10

本预发布版本为浏览器 `CanvasContextHost` 补上当前路径的类型化填充与两种原生曲线。它解决 [#143](https://github.com/calcit-lang/js-ffi/issues/143) 指出的模块基础 API 缺口，让 Quamolit 等消费者能够逐步移除单用途 `(c)=>{c.fill();}` inline JS 和为此添加的局部 `unsafe-coerce`。本版本只发布通用 Canvas2D 能力，不包含 Scene、动画、采样或后端选择策略。

## 新增接口

- `context .fill!`：无额外参数，返回 `Unit`，映射原生 `fill()`。
- `context .arc! x y radius start-angle end-angle counterclockwise?`：五个 `Number` 和一个 `Bool`，返回 `Unit`，映射原生 `arc`。
- `context .bezier-curve-to! c1x c1y c2x c2y x y`：六个 `Number`，返回 `Unit`，映射原生 `bezierCurveTo`。

三个方法都是 `:js-ffi` 浏览器目标下的 typed external-object trait 成员，不增加新的 JS wrapper、公开 `Dynamic` 或 `unsafe-coerce`。`fill()` 使用当前路径与填充样式；`save/restore` 恢复样式、变换和裁剪但不恢复路径。半径、角度、控制点的值域遵从浏览器语义，静态 `Number` 类型并不担保数值有限或半径非负。

## 验证与后续迁移

关联 [PR #144](https://github.com/calcit-lang/js-ffi/pull/144)。使用仓库固定的 Calcit `0.24.3` 与 Node `24.4.1`，完整 `yarn test` 通过：browser public check 258/258，50 个非法类型消费者被拒绝，21 项 Node 测试和 516 条真实 Chromium 断言通过。独立 Calcit recipe 与原生 Canvas 逐像素对照，并用“只有填充”及“只有描边”作为反例控制；WebGPU 因测试机无 adapter 继续跳过。

当前仓库的 Yarn 配置对新 npm 包有 1 天 `npmMinimalAgeGate`。虽然全局 Calcit 已安装 `0.25.0`，本模块仍使用可安装且固定的 Calcit / `@calcit/procs` `0.24.3`；不要为这项 Canvas 能力跳过依赖等待策略。待本版本的 `deps.cirru`、`package.json`、annotated tag 与 GitHub prerelease 一致，且精确 main SHA 的 Check 成功后，下游才升级。Quamolit 删除项目内 inline fill 适配并完成消费者测试后，#143 的验收才算结束。
