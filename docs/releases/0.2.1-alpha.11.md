# js-ffi 0.2.1-alpha.11

本预发布版本对齐实际已发布的 Calcit CLI / npm `@calcit/procs` **0.28.0-alpha.3**，与模块自身版本 `0.2.1-alpha.11` 区分。关联 [#150](https://github.com/calcit-lang/js-ffi/issues/150) 和 [Calcit 0.28 milestone](https://github.com/calcit-lang/calcit/milestone/56)。本模块仍通过 Git tag 分发，不发布 npm 包；npm 中的 `@calcit/procs` 是 Calcit runtime，不是这个模块。

## 变化与边界

- 包含既有 Option 方法迁移，避免继续推荐兼容 helper。
- 浏览器 `DomElementHost` trait 断言采用显式类型引用，保留 DOM 宿主实际契约检查，不通过扩大 Dynamic、添加 unsafe 或删除断言绕过类型检查。
- `deps.cirru`、npm runtime 和 lockfile 使用相同已发布编译器版本。Yarn quarantine 的例外仅限精确 `@calcit/procs@0.28.0-alpha.3`，不是关闭所有依赖的等待策略。
- 公开 API 和异步、取消、文件、浏览器资源等语义不夹带改变。已有 48 处已审阅的宿主断言 baseline 不增加；它不是运行时数据正确性的证明。

## 升级顺序

只有 `0.2.1-alpha.11` annotated tag 与 GitHub prerelease 发布后才更新应用的模块依赖，不能把尚未发布的 main 当成发布版。

1. 安装 Calcit CLI `0.28.0-alpha.3`，核对 `calcit -v`。
2. 将应用 `deps.cirru` 的 Calcit 版本与 npm `@calcit/procs` 精确版本同时调整为 `0.28.0-alpha.3`，再更新 js-ffi 模块版本为 `0.2.1-alpha.11`。
3. 执行模块安装与 npm 安装，确保所有依赖使用同一个 runtime 实例；不要只用下游 resolution 长期掩盖模块版本错位。
4. 运行 `caps verify --toolchain`、应用严格检查、实际 Node/browser 构建和项目测试。针对升级写法，用现有 `core-api-0.28` preset 先预览，再按 revision 安全应用；未知、宏或业务语义边界保留人工审阅。

Calcit `0.28.0-alpha.3` 仍是预发布版本，不代表 Calcit 0.28 milestone 全部完成。本模块也不要求下游使用 PR #1592 的未发布源码。

## 已验证的源码组合

升级源码见 [PR #152](https://github.com/calcit-lang/js-ffi/pull/152)，合并 main `d54ad80827f2697f3401124319c8641573c8875d` 的 [Check](https://github.com/calcit-lang/js-ffi/actions/runs/36800216038) 成功。实际 crates.io CLI 和公开 npm runtime `0.28.0-alpha.3` 配合 Node `24.19.0` 运行完整 `yarn test`：315 个公开 API 条目、8 个 recipes、全部 Node/browser 静态入口、50 个错误消费者、21 项 Node 测试、15 条 WebGPU capability 断言以及 516 条真实 Chromium 断言通过。真实 GPU 执行因机器没有 WebGPU adapter 明确 skip，不宣称 GPU 路径已执行。

在现有 preset 下，模块预览没有改写建议，guarded apply 无修改，再次预览为空。浏览器构建通过；代码格式化无变化。此证据证明升级源码组合，不代替最终发布 tag 的精确 main CI 和实际下游安装验证。发布准备 PR 完成后仍须核对那些门槛。
